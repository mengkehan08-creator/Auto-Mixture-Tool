# 训练 Token 预算

训练配置页使用可编辑的 `training.token_budget`，默认 401,395,843 Token。
该值来自当前 d24 参数量 729,810,624 × 数据比例 0.5 × 1.1，取整数。
这是当前配置的默认值，不是所有模型通用的推荐值；更换模型后应重新设置。

所有配比方案共用该训练预算，不改变配比作业生成的采样集大小。
实际步数为 `ceil(token_budget / total_batch_size)`；因此实际处理量可能略高于预算。
预算超过采样集规模时，训练数据可能被重复使用。

旧 API 未提供 `token_budget` 时仍使用 dataset_stats.json 中的共同预算；
旧 API 的固定 `num_iterations` 仍兼容，但不能与 Token 预算同时设置。
复制旧作业到页面时，若原配置没有 Token 预算，将使用页面默认值，需要重新核对。

## 2026-09-09 评测错误

日志首先在 worker-1 的 `offline_base_eval` 中出现 `No checkpoints found`，
路径是该节点 `/tmp/.../nanochat_model/mid_checkpoints/<模型标签>`。
当前训练和评测均使用多节点启动，但本地目录不是共享存储。
日志证明第二节点没有可加载的模型；仍需 worker-0 的训练保存日志确认模型是否完整保存。

保留多节点评测的修复方案：训练完成后，由首节点验证 checkpoint 文件完整性，
发布模型文件和完成清单，再由其他节点同步并校验，通过后一起启动评测。
只有 OBS 时，不能把各节点同名本地输出目录当作共享目录，也不能假定作业结束时的
OBS 上传能在同一作业的评测阶段提供完整模型。
另一方案是仅在首节点评测，但会改变现有多节点评测方式，需确认后实施。

末尾 `ascend_fd` 无法把 `1200.00` 转为整数是平台诊断组件的二次错误，
不能通过修改训练步数解决。该平台组件未修改。

后续实现已将新实验拆为配比、训练、评测三个独立作业，评测挂载前序训练的 OBS 输出，
不再依赖前序容器的 /tmp 目录。详见 THREE_STAGE_WORKFLOW.md；集群实跑仍需验证。
