# 从指定阶段重新执行

本文说明旧版三个阶段的重试。新版每策略独立配比/训练的实验，可在具体作业卡片直接重试，详见 [独立策略作业与跨实验模型评测](PARALLEL_STRATEGY_JOBS.md#失败与重试)。

在“实验作业 → 查看作业详情”中操作。仅支持新版拆分流程、已结束且前序阶段成功的实验；正在运行、提交结果待核对、申请删除的实验不能复用。

| 操作 | 复用的 OBS 输出 | 新提交作业 |
|---|---|---|
| 训练阶段重试 | 原实验采样集，保留策略 ID、比例及采样统计 | 训练，以及启用时的评测 |
| 评测阶段重试 | 原实验模型目录和 models_manifest.json | 仅评测 |

1. 修复代码后，先更新任务使用的 OBS 代码目录；若更改了工具后端，重启开发环境服务。
2. 点击对应按钮，在当前作业详情中展开重试编辑区，不跳转到创建实验页面。核对只读的采样集或模型输入地址。
3. 在编辑区调整节点数、训练预算或评测参数；已完成阶段不允许修改。评测复用时保留原模型及 Tokenizer 配置。
4. 展开“运行资源与任务配置”，核对镜像、依赖挂载、输出地址和 command。重试默认重新加载当前工具的启动命令；原自定义命令如需保留，请重新填写。
5. 点击“提交阶段重试”，直接调用后端提交剩余作业。创建新的重试记录、ModelArts 作业和独立输出目录，原实验不被覆盖。原实验详情中可查看关联的重试记录；复用阶段显示“不提交此作业”。

训练阶段重试是重新训练模型，不是恢复失败训练的优化器状态或中断步数。

必须保留原 OBS 采样文件，或模型清单及其引用的权重、元数据。工具根据原作业成功状态确认可复用，不在开发环境读取 OBS；挂载后由对应作业检查文件。OBS 文件被手动删除时仍会失败。删除重试实验不会终止原实验作业，也不会删除 OBS 文件。

API 仍使用 `POST /api/v1/workflows`，在完整配置中增加：

```json
"reuse": {"workflow_id": "原实验的12位ID", "stage": "evaluation"}
```

`stage` 可为 `training` 或 `evaluation`。后端从原记录解析输入地址，不接受客户端伪造前序输出；前序配置以原记录为准。使用同一个 `request_id` 重复提交相同配置不会重复创建实验。
