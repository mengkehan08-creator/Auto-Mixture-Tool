# 同类型历史模型对比

## 页面操作

1. 在训练配置中选择本次基础模型 OBS 地址与标签（默认 `d24`）。
2. 打开评测配置的“加入历史模型对比”。只有“同类型”和“有差异”两个分类，默认显示“同类型”；点击“有差异”查看全部差异模型（仍按每页 5 条分页）。
3. 搜索模型名称或来源实验，支持多关键词、多选。展开模型详情，在“本次配置／历史模型”对照表中查看参数：相同为绿色、已知不同为红色、未记录或未读取为灰色，并附文字标注。多策略训练配置分别对照。
4. 两类模型均可勾选，进入任务配置检查后提交。本次训练的全部策略模型仍自动加入评测。

修改本次配置后会重新比较，已选模型不被静默删除。后端不因模型之间参数不同或缺少历史指纹而拒绝提交；仍要求所选模型训练成功，并且评测器支持其框架。

## 判定标准

| 判定 | 条件 | 可否加入 |
| --- | --- | --- |
| 同类型 | 已记录且可比较的参数未发现差异；清单不完整时另行提示实际文件未核验 | 可以 |
| 有差异 | 至少一个可比较的已知参数不同 | 可以 |

节点数仅作为作业信息展示，不参与差异判断；输出保存地址也不属于模型训练参数。信息缺失不作为参数差异，必须结合“实际文件未核验”提示理解“同类型”：它可能只表示已保存的配置一致，不代表已经证实权重文件相同。

模型名称、`d24` 标签、OBS 目录相同都不是实际权重相同的证据。结构、Tokenizer 和基础权重指纹从模型清单补充；训练框架和训练参数可从本地实验提交记录读取，无需依赖 OBS 清单。

“同类型”不等于公平对比已经验证。训练 Token 预算、单卡批量、序列长度、学习率、优化器、全局批量不同或未记录时会提示；候选数据集地址不同也会提示。相同 OBS 地址不保证数据版本一致，实际消耗 Token 数、随机种子与训练完成情况仍应结合报告核对。提示会写入对比报告。

修改后重启 UI 后端，确保启动服务的账号和容器能看到该目录。映射使用完整目录边界，并阻止路径穿越和指向挂载根目录外的符号链接；只读取允许的 JSON 清单。工具不会自动挂载磁盘。

## 一次性生成基础模型身份清单

在开发环境已有完整基础模型目录的情况下执行；命令只读取本地文件，不联网、不上传。`--model-dir` 是包含 `base_checkpoints/d24/` 与 `tokenizer/` 的目录，不是 `mid_checkpoints/`。

```bash
cd /home/ma-user/work/Auto-Mixture-Tool
export PYTHONPATH="$PWD:$PWD/src:${PYTHONPATH:-}"
python -m auto_mixture_tool.modelarts.model_comparison \
  --model-dir /home/ma-user/work/nanochat_model_dir \
  --tag d24 \
  --output /home/ma-user/work/model_identity_d24.json
```

将生成的 `model_identity_d24.json` 上传到页面所填的基础模型 OBS 根目录，和 `tokenizer/`、`base_checkpoints/` 同级。文件必须对应实际上传的同一份模型目录。更换基础权重或 Tokenizer 后需重新生成；命令拒绝覆盖已存在的输出文件，请先另存旧清单或使用新的输出位置。

权重指纹记录 `base_checkpoints/<标签>/model_*.pt` 文件集合，不是模型名称，也不表示已推断外部训练脚本实际选择了哪一个 checkpoint。自定义启动命令必须遵守相同初始化和清单协议。

## 新训练与旧模型

新版本内置训练入口在首节点训练前读取挂载的基础权重和 Tokenizer，计算 SHA-256；训练完成后将指纹与最终 checkpoint 的真实结构写入 `models_manifest.json` 的 `comparison_identity`。这会增加一次本地权重读取，不增加训练步骤或网络下载。

旧版训练产物没有指纹时不能凭现有目录补猜，但仍可按已保存的参数分类和选择，并显示实际文件未核验。只有能从原始训练记录确认当时使用的基础权重、Tokenizer 和最终结构，才可由管理员基于原始文件核对并补齐对应清单。不应把当前基础模型清单直接套在所有旧模型上。

新页面使用 `comparison_policy: allow-differences`。评测逐个加载各自模型和 Tokenizer，允许模型之间结构、基础权重、Tokenizer 等不同，不做跨模型相等性拦截。仍核对单个模型自己的文件完整性、实际结构与已记录结构、实际 Tokenizer 与已有指纹，防止文件替换或损坏；旧清单没有指纹时不强制要求补齐。缺失 checkpoint 或评测器无法加载的模型仍会报错，“可选择”不意味着任意模型格式都能运行。

已保存的旧 `same-model-type` 实验保留原严格运行策略；新建及重新提交历史模型选择使用允许差异的策略。对比报告保留差异与条件提示，不把不同条件的结果解释成纯配比策略收益。

## 接口

`POST /api/v1/models/compare` 接受 `model_obs_uri`、`base_model_tag`、`input_data_obs_uri`、`training_configs`，返回模型列表及 `comparison.status/reasons/warnings`。候选模型地址来自工具保存的成功训练记录，不能在此请求中任意指定候选权重地址。

该接口只做核对，不创建 ModelArts 作业。部署仍应遵守工具现有的内部可信用户访问约束，避免向公网开放。
