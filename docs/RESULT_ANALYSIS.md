# 实验结果分析

## 使用

在“实验作业”的列表或详情点击“结果分析”。独立评测成功后，页面读取该实验已保存的报告输出地址并自动分析；无需再次起 ModelArts 作业，无需填写报告路径或调用大模型服务。

页面展示共同评测项平均正确率、可切换的单项对比图、逐项得分、模型 checkpoint、已记录的采样 Token 数和领域配比、客观结果解读及可比性限制。支持当前模型与历史模型共同评测。可返回原作业详情。

未完成评测时显示等待提示。评测成功但 OBS 文件尚未同步时显示具体读取提示，稍后点击“刷新结果”。有多个评测包时按包分别分析；部分报告读取失败会显示“不覆盖全部评测集”，不冒充完整分析。旧版没有独立评测作业的实验暂不支持此入口。

## 数据来源与部署

读取现有 `comparison_report.json`，不会下载模型权重或扫描整个 OBS。内置评测使用报告根目录；同时配置自定义评测包时，使用 `builtin/comparison_report.json` 和 `package_0/comparison_report.json` 等现有输出目录。

默认 OBS 前缀 `obs://bucket-pangu-green-guangzhou/s00944147/l00916525/` 映射到 `/l00916525/`，与模型信息读取一致。若部署环境不同，在启动工具前设置：

```bash
export AMT_OBS_MOUNT_ROOT=/l00916525
export AMT_OBS_MOUNT_PREFIX=obs://bucket-pangu-green-guangzhou/s00944147/l00916525/
```

工具进程需要报告的只读权限。前缀外的报告需要环境提供 MoXing 和 OBS 只读权限；不会拿 ModelArts Authorization 当 OBS 凭据。JSON 报告限 8 MiB，防止异常大文件占用服务资源。仅从已记录的实验输出地址构造路径，接口不接受任意文件地址。

更新开发环境工具代码并重启服务即可分析此前已经生成的符合格式的报告，不需要重跑训练。UI 资源通过 `npm --prefix ui_demo run build` 更新；仓库包含构建结果，部署端无须运行 Node。

接口：`GET /api/v1/workflows/{workflow_id}/analysis`。状态为 `ready`、`partial`、`pending` 或 `unavailable`。读取与分析不改动原始报告。

## 分析口径

- 正确率原始范围为 0–1，页面转换为百分比；差值报告为百分点。
- 平均正确率只使用全部模型都有有效分数的共同评测项，各项等权。不把缺失分数补成零，不混入 CORE/STEM 汇总行，也不把该均值称为官方综合分数。
- Centered 和报告已有的 CORE/STEM 汇总值单独展示，不与正确率混排。并列得分如实标记。
- 不跨评测包合并同名任务。模型、基础权重、Tokenizer、训练预算等不同或记录不完整时给出提示；节点数不作为模型类型差异。
- 采样配比只显示有明确对应关系的已记录统计；无法对应某个策略时标为未记录，不猜测。采样 Token 数不等于训练实际消费的 Token 总数。
- 文案采用确定性规则，不联网调用语言模型。单次得分差不能证明统计显著或策略具有因果优势；没有多随机种子重复实验时不生成显著性结论。

设计采用 scientific-critical-thinking 技能的证据边界原则，区分观测结果、可比性和因果推断。
