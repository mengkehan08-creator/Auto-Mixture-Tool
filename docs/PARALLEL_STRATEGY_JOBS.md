# 独立策略作业与跨实验模型评测

## 运行关系

新建页面使用 `execution_mode: parallel`。旧实验仍按原版本展示和恢复，不会自动增加云作业。

```text
QuaDMix 配比 ──成功──→ QuaDMix 训练 ──┐
人工配比    ──成功──→ 人工策略训练 ──┼──全部成功──→ 汇总评测 → 对比报告
随机配比    ──成功──→ 随机策略训练 ──┘                ↑
                                    创建时所选的历史成功模型
```

每个配比作业独立提交，自己的配比成功即可提交训练，不等待其他策略。
三个策略启用评测时共 **7 个作业**：3 个配比、3 个训练、1 个评测。
关闭评测则为 6 个；选择历史模型不会额外训练这些模型，也不会增加评测作业数量。
“并行”指不在工具中串行等待，实际启动仍取决于 ModelArts 的资源配额与排队情况。

每个作业节点数独立设置为 1–16。QuaDMix 支持多节点代理实验；NanoChat 使用所选训练节点。
**当前内置人工/随机采样由首节点处理，建议各设 1 节点；增加节点不会加速这些采样实现。**
评测节点数、每节点设备数及评测批量单独设置，默认 1 节点。未新增训练框架或自动评估 API。

## 在页面操作

1. **配比策略**：填写已准备的 Parquet OBS 地址与输出根目录；增加或删除策略。
   每项分别填写配比节点数、优先级及作业名称。人工/随机可继续使用内置方式、OBS Python 脚本或本地上传脚本。
2. **训练配置**：每项策略分别配置训练节点数、训练作业名称、保存模型名称。
   每个作业直接显示默认可编辑的 Token 预算、批量和验证间隔，无需勾选开关。
   训练从基础模型独立初始化，不是在另一个策略的训练结果上继续训练。
3. **评测配置**：选择评测集、评测节点数、批量、优先级、作业名称和报告地址。
   在“加入历史模型对比”中勾选其他实验训练成功的模型；本次所有策略的模型自动加入。
   可搜索模型名称/来源实验，多个关键词以空格或逗号分隔，匹配任意关键词；每页显示 5 个模型，跨页及更换搜索后保留多选。
   点击“查看模型参数与保存地址”展开配置。
4. **任务配置**：核对每个作业的 `name`、`node_count`、`priority`、依赖关系和作业总数。
   公共 `command` 可直接编辑，也可展开某个策略单独设置配比/训练命令。
   自定义命令仍须生成约定的采样和模型清单，不能只返回退出码 0。
5. 点击“检查配置”，通过后再提交。工具不下载 OBS 文件；由 ModelArts 挂载到各作业，运行前检查实际数据和模型。
6. **实验作业详情**：查看每个作业的状态、独立节点数、ModelArts 链接、输入输出地址和错误信息。
   进度表示作业状态，未提供虚构的训练耗时百分比。

各训练作业的参数独立保存。不同 Token 预算会影响对比公平性，正式实验建议保持相同预算并在报告中保留配置。

## 名称与模型记录

- 每个云作业可手动填写名称，也可留空自动生成，例如 `training-2node-时间-实验编号-序号`。
- 手动作业名以英文字母开头，1–64 位，可含字母、数字、`_`、`-`。
- 提交时检查同批次及工具保留的历史作业名称，大小写不区分；重名禁止提交。删除实验也不释放历史名称。
- 检查范围是**本工具记录**，不扫描工具之外创建的全部 ModelArts 作业。后端保持单进程运行，勿使用多个 Uvicorn worker 共用同一记录目录。
- 模型名称可使用中文；模型唯一身份是 `实验 ID:策略 ID`，同名模型仍按唯一 ID 区分，不覆盖模型文件。
- 页面展示提交时的训练配置、来源策略、节点数和 OBS 地址。实际 checkpoint 步数及模型结构记录在输出的 `models_manifest.json` 中，工具服务器不直接读取 OBS 权重。
- 只有对应训练作业成功的模型才可选；即使另一个策略失败，已经成功的模型仍可用于其他实验评测。
- 模型列表由持久化实验记录恢复。删除实验不删除 OBS 文件，已成功模型的记录仍可选择；不要手动删除服务器的 `result/.workflows/`，否则无法恢复模型索引。

## 输入输出如何衔接

假设实验输出根目录为 `obs://桶/目录/`，本次实验名为 `实验名-时间-编号`，策略 ID 为 `manual_2`：

```text
obs://桶/目录/runs/实验名-时间-编号/
  strategies/manual_2/
    mixing/              配比相关输出（QuaDMix 作业）
    sampled/data/        此策略的 Parquet 分片、dataset_stats.json、人工方案清单
    sampled/experiment.log
    training/results/    此策略的训练日志
```

配置了模型输出根目录时：

```text
模型输出根/runs/实验名-时间-编号/manual_2/
  模型标签目录/model_XXXXXX.pt
  模型标签目录/meta_XXXXXX.json
  models_manifest.json
```

未配置模型输出根时，模型存于实验的 `training/checkpoints/策略ID/`。
模型显示名称保存在清单与模型索引中；实际 checkpoint 目录沿用 NanoChat 标签规则。
配置了报告根目录时，对比结果位于 `报告根/runs/实验名-时间-编号/`，包含
`comparison_report.json`、`comparison_report.md` 及各模型的独立 CSV。多个评测包分别使用报告子目录。

训练输入自动使用对应配比输出的 `sampled/`。评测自动将各训练输出分别挂载为
`evaluation_model_0`、`evaluation_model_1` 等，并分别挂载各自的 Tokenizer。
同名 checkpoint 或相同训练步数不会覆盖其他来源的模型或 CSV。
当前跨实验评测要求模型与所用 NanoChat 评测代码兼容，不等同于支持任意 Hugging Face 架构。
运行时只选择清单中指定策略的最终 checkpoint，验证文件后评测；实际模型结构也写入报告。

## 失败与重试

一个策略失败时，不终止其他正在运行的独立分支；其下游训练不提交。
只要有一个必需训练未成功，汇总评测就不提交，并明确显示前序失败。
创建请求超时或缺少作业 ID 时标记“待人工核对”，不会自动重复提交付费作业。

实验全部结束后，可在具体作业卡片点击“配比阶段重试 / 训练阶段重试 / 评测阶段重试”：

- 直接在详情里编辑节点数、优先级、命令，以及训练预算/批量/间隔或评测批量，不跳回创建向导。
- 配比重试：重建该策略配比、该策略训练和汇总评测；其他成功模型复用。
- 训练重试：读取原配比的**同一 OBS 采样地址**，重建此训练与汇总评测。
- 评测重试：复用全部原训练模型地址，仅提交新评测作业。
- 新重试记录与原实验关联，输出使用新的实验目录；原输出不覆盖，不共享远程作业 ID。
- 其他失败分支不会被此次重试偷偷启动，仍会阻止最终评测；可在新的重试记录中继续修复该分支。
- 改基础模型或 Tokenizer 会影响采样统计，不能仅作为训练重试参数修改，应新建实验重跑采样。

## 开发环境部署

先将**本次更新后的完整工具目录上传/同步到任务配置的代码 OBS 目录**，并在开发环境更新同一版本。
只更新开发环境 UI，不更新 OBS 代码，会造成新配置进入旧容器代码。

```bash
cd /home/ma-user/work/Auto-Mixture-Tool
# 使用已经配置好的 Python 3.11 服务环境；存在虚拟环境时再激活
if [ -f .venv/bin/activate ]; then source .venv/bin/activate; fi
export PYTHONPATH="$PWD:$PWD/src:${PYTHONPATH:-}"
python -m auto_mixture_tool.cli --workspace "$PWD" serve --host 0.0.0.0 --port 8080
```

保持该服务运行以监控状态和自动提交后继作业。重启会恢复已记录作业的查询，不重新创建已知 ID。
通过原有 JupyterLab 代理 `/proxy/8080/ui` 打开界面，刷新浏览器获取新版本。
身份认证沿用开发环境私有 IAM 配置；不要把真实 Token/secret 上传到 GitHub 或代码 OBS 包。
离线依赖仍沿用已有挂载，无新增第三方 Python 包。

## API 新字段

原请求中的数据、资源、公共训练配置和 ModelArts 设置保持不变，新增字段如下：

```json
{
  "execution_mode": "parallel",
  "strategies": [
    {
      "id": "quadmix", "type": "quadmix", "name": "QuaDMix",
      "mixing_nodes": 2, "mixing_job_name": "", "mixing_priority": 1,
      "training_nodes": 4, "training_job_name": "", "training_priority": 1,
      "model_name": "QuadMix正式模型",
      "proxy_experiments": 16, "proxy_steps": 15, "search_count": 1000,
      "training": {"token_budget": 401395843, "device_batch_size": 1}
    }
  ],
  "evaluation_nodes": 1,
  "evaluation": {
    "job_name": "", "priority": 1, "datasets": ["stem"],
    "model_ids": ["历史实验ID:random"]
  }
}
```

以上是新增字段示例，不是省略资源配置后仍可独立提交的完整请求。
`GET /api/v1/models` 获取可选成功模型及配置。
`POST /api/v1/workflows/{实验ID}/jobs/{作业key}/retry` 在详情直接重试，例如请求体：
`{"nodes": 3, "name": "", "training": {"token_budget": 1048576}, "request_id": "唯一请求标识"}`。
不传 `execution_mode` 的旧 API 请求继续使用串行模式，保证已有客户端兼容。

本机使用模拟 ModelArts 响应验证调度、依赖、失败隔离、持久化恢复、重名拦截、跨实验模型挂载和重试地址。
前端已构建并运行逻辑测试。真实 NPU 训练、平台配额、OBS 权限及多节点通信仍需在目标环境验收；本机测试不代表云上全链路已经跑通。
