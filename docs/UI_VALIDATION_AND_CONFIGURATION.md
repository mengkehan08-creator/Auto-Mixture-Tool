## 配比数据与策略

- 输入：规范化 Parquet 目录。示例：`examples/datasets/quadmix_parquet.py`。
- 填写 OBS 地址后自动在后台检查所有分片字段和类型，每片均匀随机抽取 3 条不同记录（不足 3 条则全取）；页面轮询结果，不在一个 HTTP 请求中等待所有文件读取完成。文档数来自 Parquet 元数据，文件大小来自挂载文件信息。各片按抽样文本平均字符长度 × 文档数 ÷ 4 汇总估算 Token，不再全量扫描长度列。Parquet 仍需解码抽中记录所在的行组，不代表底层只读取三条记录的字节。
- 校验通过后才能提交；提交时仅检查服务端已通过的输入数据校验记录，不重新读取输入数据。记录有效期为 1 小时，服务重启后失效；过期或更换地址需重新校验。同一地址内容改变时，用户应点击“重新校验”，不能沿用旧结果。云作业启动仍检查实际挂载输入。评测包的独立校验逻辑不变。
- 每片 3 条是格式抽查而非全文合格保证；长度差异大的数据、中文和代码的 Token 估算可能明显偏离实际。输入数据集预计 Token 数只由数据决定，不与训练预算同步；参数范围改变时各策略预计最终采样 Token 数自动更新，实际值以算法输出统计为准。
- 每个策略标题旁可打开说明。人工与随机提供脚本下载，脚本接口仍为 `STRATEGY_API_VERSION = "1"`、`select(pool, context, config)`。
- 样例位置：`examples/strategies/manual_quality_first.py`（实际按长度优先）、`examples/strategies/random_length_aware.py`（按长度分桶随机）。这些是自定义策略示例，不是默认采样算法的同义替代。
- 代理实验步数旁显示每组预计训练消耗：步数 × 8 × 2048 Token，不乘代理实验数，不乘节点数；自定义 command 改批量或序列长度后需重新核算。代理实验数默认 50，建议不少于 50，但不是效果保证。
- 最终采样实际值在创建时仍为“待统计”。数据校验后显示参数范围中点与端点的采样情景估算：输入估算 Token × 采样函数在排名 0～1 的积分。假设 Token 加权排名连续，未计后续过滤、裁剪，重复记录计入；不是最终搜索结果或统计置信区间，不以历史固定数值作标准。

### QuaDMix 搜索范围

每个策略可独立编辑有效参数的下限和上限；相等表示固定参数。默认 ω=[0,0.1]、ε=[0,0.001]、λ=[0,1000]、η=[0,1]。ω/ε/η 限制在 0～1，λ 必须有限且非负，上限不得小于下限。参数实际传到代理候选生成与最终搜索，Top-K 平均仍在范围内。

请求字段为 `sampling_bounds`；YAML 使用 `algorithm_config.sampling_bounds`，例如：

```yaml
sampling_bounds:
  omega: [0, 0.2]
  epsilon: [0, 0.002]
  lambda: [0, 1000]
  eta: [0, 1]
```

ω 决定优先选取的质量排名区域；ε 是所有文档的基础选取率（尾部仅使用此值）；λ 和 η 调节优先区域强度。其他参数固定时提高这些值通常增加总入选次数，但不等于增加唯一文档，也不保证搜索后的训练效果改善。自定义启动命令必须仍调用工具入口并传递参数。

## 统一训练与重复风险

一次新实验共用训练框架、基础模型、Token 预算、每节点设备数及隐藏的训练参数。各作业独立名称、节点数、优先级及 command 保留。单卡批量、验证损失检查间隔和训练期间任务评测间隔仅隐藏，后台默认值仍为 1、-1、-1。

数据输入阶段仅显示输入数据量和各策略预计采样量，不设置训练预算。训练配置阶段根据独立填写的训练预算显示重复使用风险。输入数据校验后，根据数据 Token 估算量及当前 ω、ε、λ、η 范围自动计算参数中点情景采样量，无需手动提供实际采样统计。修改参数范围或训练预算时实时更新；更换数据地址后清除数据估算，需重新校验。未完成校验或参数范围无效时不显示虚构倍数。训练预算 ÷ 预计采样量严格超过 3 才红色告警，不阻止提交；恰好 3 倍不告警，参数范围预计无数据时也会警告。这是提交前情景估算，不是最终参数搜索结果；采样内部重复、训练裁剪和批量取整仍影响真实重复次数。代理实验数与步数不作为最终采样量的直接乘数。

“创建实验”确认后恢复全部默认值；“阶段重试”提交前再次确认，继续复用成功的前序输出。

## OBS 评测包

在“评测配置 → OBS 路径 → OBS 评测数据”增加名称和目录地址。工具识别 JSON、JSONL、CSV、Parquet 数据，或保留已有 NanoChat 包。自动适配不会修改 OBS 原始文件；运行时在容器临时目录生成评测器可读取的副本。失败时说明文件、记录及具体原因，而不是强制要求所有题目都使用 query 字段。

可选配置示例：`examples/evaluation/basic/`。普通选择题数据无须手工创建下面这些文件；需要明确任务类型、few-shot、答案提取器或参考基线时，仍可以提供配置。

```text
basic/
  core.yaml
  eval_meta_data.csv
  eval_data/science.jsonl
```

- 题目字段可为 query、question、problem、prompt、input；选择题识别 choices/options 数组、label/text 结构或 A/B/C/D 列，答案支持零起始整数、选项标签及唯一的选项文本。
- 生成题识别 question/problem 等题目字段及 answer/final_answer/target。无配置时根据 gsm8k、math、math500 文件名匹配现有答案提取器；其他开放问答无法确定评分规则时明确提示，不擅自套用数学评分器。仅有 solution 而无最终答案暂不自动提取。
- 保留 NanoChat 原有 schema（context_options、continuation、gold）与 language_modeling（context、continuation）任务支持。
- 未提供配置时采用零样本评测；未提供基线时，选择题按均匀随机选项计算基线，生成/续写题用 0（不调整原始正确率）。这不代表官方评测协议。报告目录的 evaluation_adaptation.json 记录该适配政策；正式对比应统一任务与参数。

不能识别的问题/答案、编号有歧义、空数据、路径越界、无法确定的评分规则等会给出原因。不支持的 HumanEval / MBPP 代码执行、多模态、BLEU / ROUGE 或大模型裁判需要对应评测器，不能只靠上传数据解决。当前自动识别并不代表所有业界评测集均完成真机验证；实际运行还取决于挂载的 NanoChat 版本是否具备所需评测函数。

## 命令联动

各作业显示可编辑的完整命令，不用脚本路径代替命令。默认命令随镜像与 OBS 资源配置刷新，资源上下文以安全引用的环境变量显示。OBS 地址变化通过 ModelArts 挂载生效；容器内固定挂载路径是运行接口，不随 OBS 文件夹名变化。

当前启动命令面向 Python 3.11 / Ascend 镜像，自动定位解释器、离线安装依赖并做启动检查；不能从镜像名称推断并自动适配所有镜像版本。手工编辑的命令不被自动覆盖，点击“恢复此作业默认命令”后重新跟随配置。不要把密钥写入 command。

## 结果与预览

### 评测内存不足自动降批量

内置 NanoChat 的选择题、schema 和语言建模评分默认启用批量回退，无需在 UI 勾选。以评测批量 16 为例，当前批次出现可识别的内存不足时，依次尝试 14、12、10、8、6、4、2、1；奇数批量同样每次减 2，最低为 1。成功后使用降低后的批量继续当前评测项。下一个评测项重新从配置批量开始。

- 保留已完成批次，只重试当前未提交得分的批次，不跳过样本，不缩短题目，不减少评测样本数。复用原 NanoChat 的提示词、分词、前向评分和判分逻辑。
- 多节点各进程同步采用相同批量；即使某个进程已处理完其分片，也会参与状态同步，直至该评测项全部完成。
- 批量为 1 仍内存不足则停止，并指出可能是单题长度、选项数量、模型大小或剩余内存问题。这里的批量是题目数，一道多选题仍可能展开为多条候选序列。
- 此机制不处理模型加载前的内存不足、进程被系统 OOM Killer 杀死或 HCCL 通信故障；这些情况无法靠缩小评分批次可靠恢复。非内存错误立即报出，不当作 OOM 隐藏。逐题生成评测（如 GSM8K/MATH）仍使用原生成评测器，不受此批量参数控制。
- 日志出现 `[评测自动降批量]` 时表示正在重试。独立评测报告目录保存每个模型的 `*_adaptive_batch.jsonl`；`comparison_report.json` 中各模型的 `adaptive_batch` 记录调整和完成情况。不同批量可能引入浮点舍入差异，正式实验应保留该记录。

部署时需更新工具的 OBS 代码目录；仅更新开发环境 UI 不会改变已提交作业中的代码。无需重训模型，可复用已有成功训练输出，发起新的评测阶段重试。CPU/双进程测试不能替代目标 NPU 镜像上的验证。

### 阶段重试

在“实验作业 → 查看作业详情”点击关联作业的“训练阶段重试”或“评测阶段重试”，会立即打开配置弹窗，不跳转到创建实验。加载失败时在弹窗显示原因，可重新加载。

- 训练重试：复用此策略原采样集，可调整 Token 预算、节点/设备数、优先级及模型输出目录；只重跑该训练作业及后续依赖评测，其他成功策略不重跑。
- 评测重试：复用已成功训练的模型，可调整批量、节点/设备数、评测项、OBS 评测包及报告输出目录，仅重新提交评测。
- 可编辑工具代码、NanoChat 代码、安装包、内置评测资源地址，以及镜像等 ModelArts 参数和当前作业 command。前序采样和模型输入地址只读展示；更换基础模型或 Tokenizer 不属于阶段重试，应创建新的实验。
- 确认提交前再次弹窗确认；失败保留填写内容并显示错误。新输出按新实验目录隔离，不覆盖前序成功输出。旧版串行实验仍使用对应阶段重试表单。

结果分析顶部展示共同有效评测项平均正确率最高的模型，包含并列。新模型清单保存必要策略配置，历史未记录字段不推测。柱形和折线节点表示同一正确率，连线仅辅助比较；最高分为红色，缺失值不按零分处理。

本机安全验收可运行 `python scripts/preview_ui.py --port 8093`，打开 `http://127.0.0.1:8093/ui`。这是独立只读服务，不加载 IAM，不恢复作业，拒绝所有云作业变更。结果页的验收示例明确标记为非真实结果；正式服务不包含该示例。
