# 逻辑与模块检查（2026-09-08）

## 检查范围与证据边界

本轮审阅了 ModelArts 请求构造、IAM 配置加载、API 参数校验、策略文件传输、容器 stage_runner、NanoChat 命令构造、离线评测资源检查、采样清单跨作业路径、输出映射与恢复监控，并检查了规范契约注册表和 UI 参数映射。采用本地模拟回归；没有调用真实 IAM、ModelArts、OBS，也没有运行 NPU 训练。不能把本轮检查当作所有历史 QuaDMix/NanoChat 内核逐行审计或集群端到端验收。

## 已修复

| 问题 | 修复 |
| --- | --- |
| 原 IAM `auth.endpoint` 被错误当成作业接口限制 | 忽略该字段；IAM 固定用于获取 Token，UI `url` 独立用于创建作业。默认保留可信网关和 account 路由约束，其他网关可单独配置 |
| IAM 配置错误被显示为请求模板读取失败 | IAM 校验移出模板异常包装，保留不含凭据的具体错误；缺文件时提示检查 workspace |
| 无效私有配置可能阻止已有作业场景下的服务启动 | 恢复监控时转为 WAITING_AUTH，允许打开页面排查，不提交新作业 |
| 策略 ID 缺失、重复、非法路径字符到远程阶段才失败 | 本地校验 ID、脚本参数对象、名称换行；拒绝为 QuaDMix 配置仅适用于采样的脚本 |
| 节点/设备数、代理步数等参数被 int() 静默截断 | 工作流校验要求合法整数，验证 QuaDMix 设备数、随机种子范围与模型目录标签 |
| 配比后的随机/人工采样忽略用户设置的 seed | 所有策略记录统一到 QuaDMix seed；NanoChat 采样脚本显式接收 SEED |
| 评测预设与单任务混用导致运行器理解不一致 | 拒绝 stem/core/all 与其他项混选；关闭最终评测但保留中途评测时明确使用 stem，不再因空字符串隐式执行 all |
| 运行配置超限或第二个作业构造失败发现太晚 | 配置序列化提前检查，并在启动第一作业前构造检查两个作业请求 |
| mixing executor 固定显示 8 卡 | 使用 QuaDMix 的 devices_per_node，避免配置口径不一致 |

## 已检查但仍需整改/验收

1. **插件接口不等于任意组合已跑通。** 当前 ModelArts 两阶段运行器要求保留一个 QuaDMix，训练仅接 NanoChat。core 注册表存在其他参照组件，但没有自动接入这条生产工作流。其他算法和训练框架需新增对应适配与集群测试，不能仅改名称。
2. **上传策略不是任意训练入口。** 采样脚本只实现 select(pool, context, config)，领域比例和数据预算由工具控制。上传文件语法检查不能验证采样质量或证明代码安全，额外依赖必须离线准备。UI 隐藏比例不表示后端停止使用比例。
3. **数据处理职责未变。** 当前远程 UI 工作流读取已经准备好的 Parquet，不负责真实 Hadoop 作业提交；Hadoop 生成和发布数据仍是前置步骤。
4. **OBS 与多节点。** 配比完成后训练作业才提交，路径通过 sampled 输出衔接；但对象同步时机、各节点挂载一致性、HCCL 通信、2–16 节点实际训练和 checkpoint 汇集必须在真实集群验收。OBS 不是 POSIX 共享文件系统。
5. **对外暴露风险。** UI/API 尚无独立用户登录和隔离；自动 IAM 使用管理员身份，且支持可信用户脚本和自定义 command。只允许受控内部访问，不能直接开放公网。手动认证旧分支仍保留 verify=False；自动 IAM 分支强制验证证书。
6. **输出和评测结论。** 模型/报告使用独立输出映射，错误保留输出地址；没有实际写入 OBS 验证。指标含义、公平预算和训练收敛需用真实产物确认，代理 15 步只能作为冒烟配置。
7. **运行服务。** 本地 JSON 作业记录与进程内锁面向单个后端实例；多实例、高可用和跨进程幂等需要持久数据库或队列。断电发生在远程创建成功、作业 ID 未写回时，工具保守要求人工确认而不自动重复提交。
8. **依赖版本。** 离线预检查能发现部分缺失，但不能保证用户替换镜像或外部 NanoChat 版本后不再出错。固定镜像摘要、NanoChat 提交号和依赖清单后再做验收。

## 更新后建议验证

- 开发环境更新后重启后端；UI 的 `url` 使用真实作业 API，不必改成 IAM 地址。
- 私有文件保持仓库外，继续使用原 `auth` 字典即可。若曾单独填入错误的 `modelarts_endpoint`，更正或置空；该显式限制不会被自动忽略。
- 先验证缺少 secret、错误路径、非法策略参数能在本地报出具体原因。
- 使用已准备的少量 Parquet 和两节点、小步数测试，验证两个作业顺序、三个采样集、模型及报告输出；再增加节点数和训练预算。
